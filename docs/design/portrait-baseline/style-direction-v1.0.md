## 一、三个候选风格方向总览

| 维度 | A. 精修像素风 | B. 厚涂/半写实立绘 | C. 卡通/动漫渲染 |
|---|---|---|---|
| 成熟 RPG 对标 | 八方旅人（HD-2D）、三角战略、星露谷 | 博德之门3、开拓者：正义之怒 | Hades、火焰纹章：风花雪月 |
| 与游戏内渲染一致性 | ★★★★★ 直接同源（游戏内即 16×18 像素 sprite 12 倍放大） | ★★ 立绘与战斗小人间距大，需双套资产 | ★★★ 中等，需平面化处理才可缩小 |
| 表现力（角色魅力/种族特征） | ★★★ 受 32×40 分辨率上限约束（S3-1 已验证） | ★★★★★ 最高，细节/质感无上限 | ★★★★ 高，风格化强但弱于写实细节 |
| 游戏内小尺寸可读性 | ★★★★★ 为小尺寸而生，「一眼可读」门禁天然满足 | ★★ 缩至图标尺寸细节全损，需另做缩略版 | ★★★ 粗轮廓+高饱和，缩放尚可 |
| 制作成本（AI 多模型产出） | 中：提示词约束多，需防模型「伪像素」，产出后需人工对齐网格规范 | 低：主流图像模型最擅长，出图即用率高 | 中低：风格提示词成熟，但 8 种族特征一致性需多轮筛 |
| 捏脸系统接入成本 | 低：现有 drawSprite 链路可复用/扩展 | 高：需新建立绘展示层+头像裁切管线 | 中：需头像裁切+轮廓处理 |
| 与既有资产回归风险 | 零（延续 S3-1 规范体系） | 中：战斗场景仍是像素小人，风格断层需验收 | 低-中：同上但程度轻 |

## 二、逐方向说明与对标案例

### A. 精修像素风（延续路线）
- 对标：[八方旅人 HD-2D（Wikipedia）](https://en.wikipedia.org/wiki/HD-2D)、[Polygon：HD-2D 解析](https://www.polygon.com/patch-notes-hd-2d-adventures-of-elliot/)、[HD-2D 在国游市场流行（知乎）](https://zhuanlan.zhihu.com/p/1996523431852786562)、三角战略
- 要点：像素立绘 + 光影氛围，保留 32×40 可读性硬约束，用图像模型生成「精修像素肖像」再对齐网格
- 利：与游戏内 sprite 同源，捏脸/战斗零接入成本；红线-6 可读性门禁可直接沿用
- 弊：表现力天花板即 S3-1 教训本身——老板评价「太粗糙」的对象正是纯像素路线的产物，纯延续此方向有再次不达预期的风险

### B. 厚涂/半写实立绘（表现力优先）
- 对标：[博德之门3（D&D 官方 IP，立绘标杆）](https://www.pcgamer.com/games/rpg/the-best-d-and-d-videogame-youve-never-played-is-one-guys-outsider-art-personal-baldurs-gate-saga/)、[开拓者：正义之怒](https://store.steampowered.com/app/1849470/Pathfinder_Wrath_of_the_Righteous__Paint_of_War/)、[开拓者：拥王者](https://store.steampowered.com/app/640820/Pathfinder_Kingmaker__Enhanced_Plus_Edition/)
- 要点：成熟 RPG 捏脸系统主流做法——大尺寸厚涂立绘做展示，配小头像裁切做场景
- 利：表现力最高，AI 图像模型出图质量最稳，最贴合老板「对标成熟 RPG」的要求
- 弊：需要「立绘展示层 + 头像裁切 + 战斗小人」三层资产策略，John 渲染接入成本最高；缩略可读性需专门做头像版

### C. 卡通/动漫渲染（风格化折中）
- 对标：[Hades（Supergiant 美漫风立绘）](https://store.steampowered.com/app/1145360/)、[Hades 立绘合集](https://m.huaban.com/pins/5194374313/)、[火焰纹章：风花雪月（日系动漫立绘）](https://m.huaban.com/boards/58558185)
- 要点：粗轮廓线 + 高饱和平涂/赛璐璐，介于像素与写实之间
- 利：风格辨识度高，缩放容忍度好于写实，出图成本适中
- 弊：与本作「桌面跑团+像素战斗」的整体气质融合度需实测；8 种族特征一致性对提示词工程要求高

## 三、设计侧建议（供拍板参考，不代裁定）

推荐采用 **B 为主视觉 + A 为游戏内承接** 的组合策略：
1. 捏脸/人物形象展示层用厚涂半写实立绘（老板终选风格方向后，每对象 ≥3 模型产出候选）
2. 战斗/场景小人维持现有像素 sprite（S3-1 定稿体系不动，零回归）
3. 立绘按规范裁切出 1:1 头像供小尺寸场景使用，可读性由头像裁切规则保证
纯 A 延续有「再次粗糙」风险，纯 C 气质匹配待验证；B+A 组合在表现力与接入成本间最平衡。若老板更看重统一像素美学，则选 A 并要求图像模型产出「HD-2D 级精修」而非逐格填色。

## 四、决策流程（按新裁定）

1. 老板从 A / B / C / B+A 组合中拍板风格方向（本决策包即为终选输入）
2. 凭据到位（百炼 DashScope Key 或内置出图修复）后，按锁定方向执行 candidate-plan-v1.0.md：8 对象 × ≥3 模型/风格变体 = 24+ 张候选
3. 候选图过双审（Kevin 设计侧 + Bob 技术侧）→ 老板终选单张 → *-baseline-final.* 定稿入库
