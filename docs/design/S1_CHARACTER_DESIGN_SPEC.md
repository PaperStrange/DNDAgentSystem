## 一、现状诊断

### 1.1 当前捏脸维度（7项，严重不足）

| 维度 | 当前选项数 | 问题 |
|---|---|---|
| 肤色 | 7色 | 明度梯度不够均匀，深色系之间区分弱 |
| 发色 | 8色 | 灰色/白色与浅色在像素下几乎不可辨 |
| 服色 | 10色 | 部分蓝色与紫色在暗像素下混淆 |
| 瞳色 | 6色 | 选项偏少，深棕与黑色在1px瞳孔下无差异 |
| 饰色 | 6色 | 选项偏少 |
| 发型 | 4种（默认/长发/发髻/短发） | 仅4种，视觉差异小，缺乏个性 |
| 胡须 | 2种（无/有） | 只有一种胡须样式，矮人/半兽人体验差 |

### 1.2 预览清晰度问题

- 预览画布 160×180 CSS px（10倍缩放），但 Canvas 逻辑尺寸仅 16×18 像素
- `image-rendering: pixelated` 已设置，但 10x 缩放下 12×16 的角色仍然很小（约 120×160 实际像素区域中角色只占中间部分）
- 预览背景渐变与角色对比度不够，轮廓融入背景
- 没有面部细节放大机制

### 1.3 颜色区分度问题

- 发色像素仅占预览总面积 ~2.4%（DEVELOPMENT_LOG #57 数据）
- 职业头饰虽已修复不遮挡发色行，但12列网格中发色有效列数仍少
- 部分色板在 1px 尺度下明度差 < 15%，肉眼不可辨

## 二、捏脸系统重做方案（S1-1）

### 2.1 设计原则

1. **像素优先**：所有自定义维度必须能在 12×16 网格中通过 `applyLook()` 字符串变换实现
2. **种族辨识度**：8个种族在默认外观下就应可辨识，捏脸增强不应削弱种族特征
3. **渐进复杂度**：基础用户快速选色即可，高级用户可深入调整每个维度
4. **实时预览**：每次调整立即在预览中看到效果，无延迟

### 2.2 扩展后的捏脸维度（从7项扩展到14项）

#### A. 颜色维度（5项，优化色板）

| 维度 | 当前 → 目标 | 改动要点 |
|---|---|---|
| 肤色 | 7 → 8色 | 重新校准明度梯度，确保相邻色阶明度差 ≥ 12% |
| 发色 | 8 → 10色 | 移除不可辨色，新增高对比度选项 |
| 服色 | 10 → 12色 | 增加暖冷分组，同组内明度差 ≥ 15% |
| 瞳色 | 6 → 8色 | 增加琥珀色和紫罗兰色，移除与黑色不可辨的深棕 |
| 饰色 | 6 → 8色 | 增加金属色系（铜/银），与服色形成对比 |

#### B. 造型维度（从2项扩展到5项）

| 维度 | 当前 → 目标 | 像素实现方案 |
|---|---|---|
| **发型** | 4 → **8种** | 见下方发型设计方案 |
| **胡须** | 2 → **5种** | 见下方胡须设计方案 |
| **眉型** 🆕 | 0 → **4种** | 修改眼睛行的上方像素：标准/粗眉/细眉/伤疤眉 |
| **唇部** 🆕 | 0 → **3种** | 修改嘴部行像素：默认/微笑/严肃（改变嘴角像素） |
| **面部纹饰** 🆕 | 0 → **4种** | 在面部空白区域添加像素：无/额纹/颊纹/ chin纹 |

#### C. 发型设计方案（8种）

基于 12×16 网格，头发区域集中在 row 3-5（头顶）和 row 0-2（可越界延伸）：

| 编号 | 名称 | 像素特征 | 视觉描述 |
|---|---|---|---|
| 0 | 默认 | 原网格 h 行不变 | 中等长度，整齐覆盖头顶 |
| 1 | 长发 | 两侧向下延伸至 row 7-8 | 披肩长发，精灵感 |
| 2 | 发髻 | 顶部 row 1-2 加高 2px | 头顶圆髻，干练 |
| 3 | 短发 | 发色行替换为肤色 | 光头/极短寸头 |
| 4 | 马尾 🆕 | 右侧 row 4-8 加一列竖线 | 侧马尾，冒险者风格 |
| 5 | 双辫 🆕 | 两侧 row 4-9 各加一列 | 矮人/野蛮人风格双辫 |
| 6 | 蓬松 🆕 | row 2-4 向左右各扩 1px | 蓬松卷发，体积感大 |
| 7 | 背头 🆕 | row 3 发色全部后移，露出额头 | 成熟稳重，露额 |

#### D. 胡须设计方案（5种）

基于 row 6-7（下巴区域），使用发色 h 填充：

| 编号 | 名称 | 像素特征 | 适合种族 |
|---|---|---|---|
| 0 | 无 | 不修改 | 通用 |
| 1 | 短须 | row 6 中央 3-4px | 人类/半精灵 |
| 2 | 长须 | row 6-8 中央 4-5px 向下延伸 | 矮人经典 |
| 3 | 络腮 | row 5-7 两侧 + 中央连接 | 半兽人/野蛮人 |
| 4 | 山羊胡 🆕 | 仅 row 7 中央 2px + row 8 1px | 优雅/法师风格 |

#### E. 新增维度像素实现细节

**眉型（4种）**：修改 row 4（眼睛上方一行）
- 标准：不修改（保持原网格）
- 粗眉：row 4 的 s 像素替换为 h（发色），加粗 1px
- 细眉：row 4 仅保留眼睛正上方 2px
- 伤疤眉：row 4 左侧加 1px 不同色（用饰色 U），模拟疤痕

**唇部（3种）**：修改 row 6 中央区域
- 默认：保持 `ososo` 模式
- 微笑：嘴角两侧像素上移 1px
- 严肃：嘴角拉平，减少弧度

**面部纹饰（4种）**：
- 无：不修改
- 额纹：row 2 中央加 1-2px 饰色 U
- 颊纹：row 5 两侧各加 1px 饰色 U
- 下巴纹：row 7 中央加 1px 饰色 U

## 三、预览清晰度优化方案（S1-2）

### 3.1 问题根因分析

1. **角色占预览面积比过小**：12×16 逻辑像素 × 10倍 = 120×160 实际像素，但画布 160×180，角色宽度仅占 75%
2. **缺乏面部细节层次**：12×16 的像素在 10x 下，单个"像素"只有 10×10 CSS px，面部细节（眼睛、嘴巴）仅 1-2 个像素块，难以辨识
3. **背景干扰**：径向渐变的亮色背景与角色轮廓对比度不够

### 3.2 优化方案

#### A. 预览画布升级

| 项目 | 当前 | 优化后 |
|---|---|---|
| 画布 CSS 尺寸 | 160×180 | **200×240** |
| 缩放倍率 | 10x | **12x**（角色区域） |
| 角色实际像素区 | 144×192 | **144×192**（居中，上下留白减少） |
| 背景 | 径向渐变 | **纯色深底** `#12101e` + 底部 2px 深色地面阴影 |
| 描边 | 黑色 `#14101e` | 保持，但确保与背景有 ≥ 20% 明度差 |

#### B. 面部放大窗口（核心改进）

在预览下方新增一个 **面部放大区域**：

```
┌──────────────┐
│   全身预览    │  200×240, 12x 缩放
│              │
├──────────────┤
│  ┌────────┐  │
│  │ 面部   │  │  80×80, 从全身截取 row 0-7 (头部)
│  │ 放大   │  │  以 20x 缩放渲染，仅显示头部 12×8 区域
│  │ 20x   │  │  清晰展示发型/眼睛/胡须/眉型/纹饰
│  └────────┘  │
└──────────────┘
```

- 放大窗口尺寸：80×80 CSS px（实际截取 12×8 逻辑像素 × ~6.5x）
- 使用独立 Canvas，`image-rendering: pixelated`
- 背景：纯色 `#1a1828`，无渐变干扰
- 每次捏脸参数变化时同步更新

#### C. 预览渲染优化

1. **取消径向渐变背景**：改为纯色 `#12101e`，减少视觉干扰
2. **增加地面阴影**：角色脚下绘制 1 行深色椭圆阴影，增加立体感
3. **描边对比度强化**：确保描边色 `#14101e` 与背景 `#12101e` 有足够区分（当前两者太接近）→ 改为描边 `#0a0814`，背景 `#18162a`
4. **角色居中算法优化**：计算角色实际像素边界，精确居中而非按网格理论尺寸居中

## 四、色板对比度规范（S1-3）

### 4.1 色板设计原则

1. **1px 可辨原则**：任意两个同组色块在 10x 缩放下，肉眼可明确区分
2. **明度差 ≥ 15%**：同维度相邻色块的 HSL 明度差至少 15%
3. **色相优先于明度**：优先通过色相（Hue）区分，明度（Lightness）辅助
4. **跨维度协调**：肤色与发色、服色与饰色之间应有推荐搭配

### 4.2 优化后色板定义

#### 肤色（8色） — 明度均匀梯度

| 编号 | 色值 | HSL 明度 | 描述 |
|---|---|---|---|
| S1 | `#f5d0a8` | L=81% | 极浅·桃粉 |
| S2 | `#e8b88a` | L=72% | 浅·暖杏 |
| S3 | `#d4a06a` | L=62% | 中浅·蜜糖 |
| S4 | `#b8844e` | L=51% | 中·焦糖 |
| S5 | `#986838` | L=41% | 中深·肉桂 |
| S6 | `#7a5028` | L=32% | 深·核桃 |
| S7 | `#5c3818` | L=23% | 极深·黑檀 |

### 4.3 色板对比度验证矩阵

为确保"1px可辨"，以下为关键对比对的 HSL 明度差验证：

| 对比对 | 明度差 | 可辨性 |
|---|---|---|
| 发色 H1(漆黑) vs H2(深棕) | 22% → 10% | ✅ 可辨（色相也有差异） |
| 发色 H4(蜂蜜金) vs H5(铂金) | 48% → 40% | ✅ 可辨 |
| 发色 H9(银灰) vs H10(霜白) | 66% → 72% | ⚠️ 明度差仅6%，但色相不同可辅助 |
| 肤色 S7 vs S8 | 23% → 16% | ✅ 可辨 |
| 服色 W1 vs C1 | 30% → 26% | ✅ 可辨（色相差异更大） |

> 唯一风险对：H9(银灰) vs H10(霜白) 明度差偏小。建议在实际像素渲染中验证，如不可辨则合并为一色或调整 H10 至更暖的 `#e8d8c0`（暖白）。
