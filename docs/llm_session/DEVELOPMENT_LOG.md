## 一、目标

开发一款 **AI 主导的 DND 5E 像素风 WEB 联机跑团游戏**，核心要求：
1. 最多 5 名玩家 + 1 名 AI DM 开房联机；房主创建房间、选副本与 AI DM 人设、全程可踢人
2. AI DM 人设不少于 10 个（最终实现 12 个），基于 5E 规则书拓展性格
3. 副本为《凡杜尔失落矿坑》（官方新手套组）
4. 简化快速车卡；全员就绪自动开局；游戏中玩家显示为二维像素小人
5. 胜利条件：公开目标达成 **或** 全员各自达成开局下发的私密隐藏目标；全灭判负
6. AI DM 依据工作目录两本规则书 PDF（新手套组/城主指南）主持
7. **从游戏启动到结束完成全程模拟，验证可正常游玩**
8. （后续追加）接入用户 DeepSeek API 并验证；安全自检与加固

## 三、中途遇到的重大问题与解决经验

### 1. 回合切换不广播 → 全服死锁（最隐蔽）
怪物定时器驱动的回合推进从不通知客户端，机器人快照永远停在旧回合、永远不行动。
解决：Game 增加 onChange 回调，回合变化/怪物行动/章节切换/结束均广播房间。
经验：**服务端状态机的一切状态变化都要有对应的客户端通知机制**。

### 2. findPath 贪心 bug：玩家被"困"在店铺里
旧寻路只接受"比起点更接近目标"的节点——目标在墙后时曼哈顿距离永不改善，路径恒为空，
玩家站在店里永远走不到墙另一侧的敌人。
解决：改为**全图 BFS + 按预算截断 + 目标格被实体占据时退到最近邻格**。
经验：启发式优化不能改变正确性；地图类 bug 先用单元级寻路探测再改。

### 3. 自动游玩策略的节流死锁
节流依赖"下一张快照"触发下一次行动；若快照在节流窗口内到达，行动被吞后不再有任何状态变化 → 永久卡死。
解决：**温和节流(200ms) + 独立节拍器(400ms)主动驱动决策**，双保险。
经验：驱动循环不能依赖"下一次事件"——总要有一个主动的时钟兜底。

### 4. 先攻顺序空/含死亡槽位
战斗顺序在某次异常下为空 → 全部回合退化为座位轮转、怪物静止；
死亡实体残留槽位导致回合跳过异常。
解决：击杀时立即从 order 中移除该实体；顺序为空时自愈重建；回合换行逻辑同步修正。
经验：**战斗顺序数组要保证与存活实体集合一致**，任何实体的移除都要同步清理。

### 5. 机器人移动无效循环（11 万条消息洪泛）
策略向被树/墙阻挡的格子发移动，服务器寻路返回空路径、moveLeft 永不消耗 → 无限重发。
解决：策略改为**客户端 BFS 计算真实路径**，只发可达目标点。
经验：客户端与服务器对"可达性"的判断必须一致，否则一方会空转。

### 6. 房间 phase 卡在 intro（条件写反）
`if (game.state === 'intro') phase = 'playing'` 在 beginPlay 后恒为假 → phase 永远 intro，
踢人/离开时的 removePlayer 永不执行。
解决：intro 完成后无条件置 playing。
经验：**条件判断的时序要画出状态迁移图核对**，这种 bug 不影响主流程、只让边缘功能悄悄失效。

### 7. 踢人通知发给房主而非被踢者
handleMsg 里用发送者(player)代替受害者处理 kicked 结果，房主被清 roomCode、被踢者收不到通知。
解决：kickRoom 返回 victimPid，单独通知受害者并推送大厅快照。
经验：消息处理函数里"player 是谁"要时刻分清；涉及多方角色时用显式字段。

### 8. 对话无限循环 ×2
- 商店购买把"买入道具"误实现为"需要持有道具"，购买失败后对话框永不关闭 → 无限重买；
- 策略"情报优先"导致面对西达尔永远选问情报、永不选"解救" → 主线卡死。
解决：修正购买语义（花金币→获得道具）；对话选项优先级改为**解救类 > 情报 > 援助 > 交易**。
经验：NPC 对话树既是内容也是关卡逻辑，选项可用性/优先级要当作关卡设计来测试。

### 9. parseMap 丢弃定义字段
exit 只保留坐标、丢失 to/need/label；宝箱丢失 gold/desc → 传送"未知地点"、宝箱奖励错误。
解决：解析标记字符时用展开语法保留全部定义，坐标只是补充。
经验：解析器"精简输出"很容易丢字段；保留完整对象。

### 10. 出口无限循环（城镇↔庄园）
策略永远选第一个开放出口，清空庄园后反复进出。
解决：快照出口带 to 字段，策略**优先前往未访问过的章节**。
经验：多出口场景需要"进度感知"的目标选择。

### 11. 客户端覆盖层重复叠加
开场覆盖层每次快照重建而不清理，透明旧层挡住按钮点击（Playwright 报 pointer intercept）。
解决：renderOverlays 先清理全部 overlay 再重建。
经验：**每次重建 UI 前先清理同类型元素**，动态 DOM 的经典坑。

### 12. 摄像机 Y 偏移被写成 0
Canvas 变换表达式遗漏 Y 轴偏移，画面永远显示地图顶部。
解决：修正变换的 Y 轴平移量。
经验：像素渲染问题用"全画布采样非背景色像素数"的断言来兜底（已加入 e2e）。

### 13. 无音频设备导致浏览器报错
headless Chromium 无音频设备，AudioContext 异步报错。
解决：创建失败即静默降级；e2e 断言过滤环境类报错。
经验：环境能力差异（音频/字体/渲染）要优雅降级，别当成程序错误。

### 14. e2e 驱动进程 OOM
页面错误被无限收集进数组 → 数 GB 内存。
解决：错误去重 + 上限 50 条。
经验：**日志/错误收集必须有界**。

### 15. 平衡性迭代（多次 TPK）
机器人打法粗糙（不集火、治疗不及时），原版 LMoP 第一章 1 级队伍多次团灭。
解决：等级曲线改为序章后 2 级/城堡后 3 级/洞穴后 4 级；策略集火低血量敌人、优先治疗倒地队友；
踢人测试后按 4 人队调弱城堡/洞穴怪物。
经验：**用模拟数据校准数值**，把"踢人/掉线"等真实场景纳入平衡测试。

### 16. 误杀宿主进程（重大事故）
某次清理命令 `Get-Process node | Stop-Process -Force` 按名杀掉了全部 node 进程，
包括承载本会话的宿主（npx @deepseek-ai/dsh web）与两个模拟服务器，工具调用被中断、结果丢失。
解决：**清理一律按端口归属 PID**（Get-NetTCPConnection -LocalPort X → OwningProcess）；模拟脚本增加退出兜底清理。
经验：这是本 Session 最深刻的教训——**永远不要按进程名批量杀进程**。

### 17. 主机工具链偶发故障
输出收集器 ENOENT（自身暂存文件丢失）导致后台任务中断——非游戏代码问题，重跑即恢复。
经验：区分"我的代码 bug"与"环境故障"，避免误修。

### 18. 安全加固 6 项
重连令牌=pid 且 pid 全房间可见 → 可冒用劫持房主；WS 无 Origin 校验；无限流；路径防护不严；
隐藏目标裁定结果全队可见；LLM 提示词可被玩家昵称注入。
解决：随机秘密令牌(仅 s:hello 下发)/Origin 同源校验/60 条秒限流/resolve 路径防护/私密日志按观看者过滤/提示词注入防护声明。
经验：**本地 LAN 游戏同样是攻击面**——身份凭证不能出现在任何广播数据里。

## 四、方法论总结（可复用经验）

1. **隔离复现优先**：写最小 smoke 脚本直接构造 Game 复现问题，比在 20 分钟一轮的完整模拟里猜快一个数量级（寻路、回合、战斗均由此定位）
2. **数据说话**：给诊断加坐标/顺序/新鲜度/消息计数，一次运行拿到决定性证据（如"5 名玩家叠在 (16,5)"直接暴露墙阻隔）
3. **双层日志**：服务器端 [msg]/[move]/[disp] 与客户端动作计数对照，可精确判断消息在哪一环断掉
4. **读日志防 mojibake**：PowerShell 默认编码读 UTF-8 文件会乱码导致中文 grep 全部失效——用 -Encoding UTF8，关键 grep 用 ASCII 模式
5. **每次修复全量回归**：协议级 + 浏览器级双路模拟是最终裁判，防止修复引入回归
6. **状态机要画迁移图**：phase/turn/combat 三处状态机的隐蔽 bug 占了总 bug 量的一半
7. **动态 UI 先清理再重建**、**集合有界**、**环境能力降级**——防 UI 叠加、防 OOM、防误报
8. **数值平衡用模拟校准**：机器人是免费的 QA，先让机器赢，再谈真人体验

### 19. 车卡三连 bug 同源（B-1/B-2/B-3）

# 迭代补充（画面比例修复：B-8/B-9）

## 现象
用户反馈游戏开始后左侧画面角色/怪物/BOSS"偏长条状、展示比例不正常"，
多角色同屏时尤为明显。此前一轮只调了缩放范围，未验证真实渲染结果。

## 根因（实测数据定位，非猜测）
用 Playwright 实测三视口画布指标：
- 画布内部缓冲 1300×**480**，CSS 实际 1300×**1043** → **垂直拉伸 2.17~2.5 倍** → 所有精灵被拉成细长条
- 画布高度 1184px 超过视口 → 多角色同屏布局溢出

两个根因：
1. CSS `min-height:480px` 使挂载瞬间 getBoundingClientRect 返回 480，缓冲按错误高度创建，
   且 resize 只在挂载/窗口变化时执行 → 缓冲与CSS永久不一致，CSS拉伸缓冲
2. 高度链断裂：`#app` 缺 `height:100%` → `#screen-root` 的100%相对auto解析 → game界面被侧栏内容撑破

## 修复
- 去除 min-height 依赖；补齐 #app→#screen-root→.screen-game 全链 height:100% + min-height:0
- ResizeObserver 持续监听画布容器（任何布局时序变化立即同步缓冲）+ RAF 二次校准
- 缩放公式改为"目标可见22列×13行"（3~6倍），宽屏/窄屏人物大小都适中
- 多人同格堆叠错开绘制（6向偏移表）；名字/血条/悬浮伤害改屏幕空间固定像素（不随SCALE变形）

## 经验
1. **"看起来被拉伸"= 画布缓冲与CSS尺寸不一致**：先测 buffer vs rect，再查布局时序
2. **flex 高度链每一环都要 height:100%/min-height:0**，断一环内容就撑破容器
3. **用 ResizeObserver 而非一次性 resize**——侧栏渲染、媒体查询、窗口变化都会改变容器
4. **验证要实测**：canvas-probe 三视口输出 stretchX/Y 与内容长宽比，数据说话
5. **不要凭空猜渲染问题**：上一轮只调 SCALE 没有解决真实病根（缓冲拉伸），本轮实测定位后一次修好

## 修复后全量回归
- tools/canvas-probe.mjs 三视口实测：stretchX/Y=1.000、画布贴合视口（854/1034/722）、内容比例1.47/2.15/2.26
- npm run e2e 重跑：5页面完整通关（终章·回声波洞穴），公开目标胜利/击败涅兹纳尔/覆盖全部章节/隐藏目标下发/DM旁白存在/像素画布渲染正常 全部 ✅，浏览器错误0 → E2E RESULT: PASS
- e2e 截图按新渲染重新生成（31张章节截图 + 3张canvas-probe探针图）

## 本批新踩的坑与经验
### 24. 断言时机竞态（solo-probe 首次失败）
自动游玩策略在断言采样前就秒杀了序章怪物 → 「怪物数=0」误报。
解决：在**首个 playing 快照**就采样（首快照采样法），而不是事后读当前快照。
经验：**快节奏系统的断言必须锚定事件发生的瞬间**，事后采样看到的已是结果。

### 25. 新增UI区块挪动了测试选择器索引
车卡界面插入「读取已保存角色」区后，`.cg-section` 序号全部后移，旧测试定位到错误区块。
解决：测试改用语义选择器（`.opt-grid`）定位，不再依赖序号。
经验：**DOM 顺序是脆弱的**——UI 与测试都要用语义类名；新增区块时主动复查下游选择器。

### 26. 一次性渲染的下拉选项会过期
「读取角色」下拉在挂载时构建，保存新角色后选项不更新，测试发现只有默认项。
解决：选项构建抽成 `refreshRosterSel()`，挂载与保存后都重建。
经验：**任何引用可变数据的下拉/列表都要有重建函数**，在数据变化点显式调用。

### 27. 权限必须双端强制
调速/暂停只在前端禁用按钮的话，机器人或直接发消息即可绕过。
解决：服务端对 game:speed/game:pause 校验房主身份返回 err；客户端禁用控件+toast+快捷键拦截做友好提示。
经验：**权限=服务端裁决+客户端体验**，缺服务端一端等于没有权限。

### 28. LLM 生成内容长度不可控
要求 150 字，模型可能只回 80 字。
解决：**长度守卫**——去掉空白后 ≥140 字才采用，否则降级到 6 条 ≥150 字离线模板（风格随机）。
经验：LLM 输出永远要有程序化验收 + 离线兜底，验收不过就当它失败。

### 29. 高光配图零资源方案
结算卡片需要一张配图，但游戏无任何图片资源、也不宜截屏覆盖层。
解决：用现有像素引擎**程序化合成** 96×64 纪念画（渐变洞窟背景+主角+BOSS 精灵+火光粒子+胜负滤镜），以 dataURL 存入卡片。
经验：像素游戏的美术资产可以由代码现场合成，体积小且与角色外观一致。

### 30. 单人平衡的缩放公式
单人 1 分钟团灭的根因是遭遇按 5 人队设计。
解决：队伍<4 人时怪物数量 `max(1, round(count*N/4))` 且不超过原值、怪物HP `×(0.5+0.5*N/4)`、单人开局药水 1→3；4/5 人队完全不变。
经验：**数值缩放要以满编队为基准不动点**，只向小队伍方向收缩，避免影响已验证的多人平衡。

### 38. 本地存储残留导致的空白页（F-1）

经验：**任何新的周期性广播/遍历，先审计注册表里的僵尸条目**；"清理"代码要验证它真的生效过
（F-2 时代该条件就已失效，只是此前没有广播源暴露它）。

### 54. 攻击触发战斗的旧测试被新规则反噬（F-29/F-31连带）
manual-mode-probe 原用"移动到怪物旁→攻击触发战斗→轮到怪物回合"验证门控；单人队序章只有1只
哥布林（B-11缩减），攻击一击秒杀→战斗结束→永远等不到敌方回合。
解决：测试改走"怪物视野察觉触发战斗"（玩家只移动不攻击，怪物存活），配合多轮察觉判定。
经验：**新系统改变战斗触发路径后，旧测试的"触发方式"要重新审视**——让被测对象存活是测试设计的一部分。

### 55. BOSS表决必须覆盖所有攻击路径（F-30）
第一版只在"视野发现BOSS"（LOS≤12）时触发表决，但战斗进行中长弓（射程15>12）可在未表决时
直射BOSS（如克拉格），BOSS被当增援击杀、表决流程从未出现（stealth-probe 抓出）。
解决：actAttack 对 BOSS 一律先 _openBossVote（小队已入战除外）；发现半径提到16（>最长武器射程15）。
经验：**"必须先表决"类约束要审计所有能对该目标造成伤害的路径**，只堵"发现"路径会被远程/范围手段绕过。

### 56. 调校公式要与真实等级时序对齐（F-22）
离线公式按"队伍等级 vs 章节等级上限"调整，但序章 _loadChapter 会立即把队伍升到 Lv2（上限2）→
序章调校恒为×1.0不动点。首版 tuning-probe 断言"Lv1→×0.9"得到1.0被误判为失败。
解决：单元断言手工拉回等级验证公式路径，快照断言改验城堡章（上限3→Lv2队×0.9/×0.92）。
经验：**测试数据要与机制时序一致**——自动升级发生在开局构造时，任何"开局时"的数值断言都要算上它。

### 57. 视觉修复先测色块占比再动手（F-21）
模型不能读图时，用 ImageData 直方图诊断"颜色没有明显区别"：发色像素仅占预览 0.3%
（职业头饰三行 w/d/h 完全遮住发色行）、自动描边膨胀到 29% 像一团黑噪。
修复：CLASS_TWEAK 保留发色行+头盔饰条用饰色U；描边改"洪泛只描剪影外轮廓"（内部间隙透明）；
皮肤色板拉开明度差；预览加渐变天幕+地面阴影。改后复测发色占比提升 8 倍（0.3%→2.4%）。
经验：像素美术问题 = 色块统计问题；改前测占比、改后复测占比，数字即眼睛。

### 58. 营地/表决等"冻结状态"要守住回合所有权（F-30）
自动模式看门狗会在营地休整者"思考"时把回合交棒给下一位玩家，而营地行动只允许休整者执行→
多人局营地可能卡到休整者下一轮。解决：营地期间 _endTurn 不转移回合（回补给休整者）、
休整者回合不设看门狗、_campGuard 冻结全体普通动作、离线玩家在BOSS表决中视为弃权不阻塞。
经验：**冻结类状态（营地/表决）要把"谁的回合/谁有动作权"一起冻结**，否则异步驱动源会破坏不变量。

### 59. 动态难度与既有平衡基线会打架（F-32 vs sim 基线）
第一次 sim 团灭在克拉格莫城堡：根因不是视野/游荡，而是 F-32 的"上章游刃有余→下章升难度"
让 5 机器人连过四章后把城堡怪物 HP 推到 ×1.2（变形怪20→24、戈洛尔28→34），叠加 F-25 阵营敏捷
先攻（变形怪DEX18 先手），4 人队 27 秒内三倒一灭。
解决：①规则书对齐的门控——**队伍平均等级低于本章等级上限时只降不升**（遭遇难度与队伍等级相称）；
②升难度步长 0.1→0.05、钳制收紧（HP≤1.25/伤害≤1.15/BOSS章HP≤1.15）；③门控在服务端强制
（不只写在LLM提示词里，LLM输出也要过 _levelGateTuning）；④游荡放缓（2.2s/步、50%停留）+策略更积极
短休（阈值0.7）与药水（0.5）。复跑 sim：public 胜利、全断言 PASS。
经验：**"AI DM 灵活调整"必须带规则书级别的硬边界**，且边界要过模拟验证——离线公式是兜底，
AI 输出再人性化也要钳制+门控两层防线。

### 60. 浏览器自动游玩的"空转烧看门狗"（e2e 蜗牛爬）
e2e 第一轮 19 分钟卡在第一章：每回合都吃满 15 秒看门狗才推进。客户端策略向被队友占据的格子
反复发移动（服务器 findPath 空路径→位置不变→策略重发），形成无进展空转；狭窄走廊（庄园1格宽）
5 人队拥堵时人人如此。
解决：①策略拥堵检测——记住发移动时的位置，下一轮决策发现位置未变即 endturn；
②自动模式在线看门狗 15s→8s（自动模式由策略驱动，8 秒足够容错）。
经验：**客户端策略的"发出去没效果"要能自证并止损**——机器驱动循环里任何无进展重试都要有
位置比对兜底；自动模式是机器上下文，看门狗没必要给人留 15 秒。

## 本批新踩的坑与经验
### 61. "开局即遭遇"的元凶是补刷怪物（F-33）
排查发现序章固定怪物距出生点≥7格、本不逼战——真正的元凶是 count 补充逻辑 `_randomWalkable()`
把怪物随机刷在出生点旁边。解决：补刷/热补刷带「远离玩家≥8格」距离约束；出生点安全筛选
（距BOSS≥17=表决半径16+1、距怪物≥视野+2）+ 全章节地图数据修订（6处出生点/怪物移位，
脚本索引级替换+parseMap复验）；怪物视野 8→6（狼/蜘蛛8、僵尸4），游荡加锚点限界6格+
未暴露怪物不进入玩家视野（遭遇由玩家主动触发）。新增 tools/spawn-safety.mjs 双重校验。
经验：**"谁把战斗带到了玩家脸上"要找全——固定配置之外，随机补刷是第二战场**；
地图手改极易错位（引号偏移/同行多次交换），用脚本+复验代替手数。

### 62. 旧探针被动等战斗会被新设计反噬（F-33连带）
iter9-probe 之前靠"怪物视野自动开战"推进 R-16 断言；F-33 让开局保持冒险中后，探针 60 秒
等不到战斗。解决：探针主动驱动房主向最近怪物移动接敌。
经验：**设计变更要审计所有依赖旧触发路径的测试**——"被动等待"型断言在新规则下必然失效。

### 63. 机器可读标记优先于文本匹配（F-32/F-37连带，最隐蔽）
sim 在克拉格莫洞穴卡死 40 分钟：怪物全灭、西达尔未救、出口未解锁→策略对锁住的出口无限重试。
根因：自动策略用 `text.includes('解救')` 识别解救选项，而 F-32 的 LLM 对话变体把选项文案改写
（'[解救] 打开笼子'可能变成'放他出来'）→ 解救选项再也匹配不到 → 主线卡死。
解决：快照与对话选项增加机器可读 `rescue: !!(need && tag==='aid')` 字段，策略只认字段；
同时约束变体提示词"方括号分类标签必须原样保留"。
经验：**AI 生成内容会破坏一切文本匹配的机器逻辑**——功能判定必须走结构化字段，
文本只用于展示；任何 `text.includes` 型匹配都要问"这段文本会被AI改写吗"。

### 64. 风筝策略是机器人团队的生存刚需（F-36连带）
远程/施法机器人贴脸输出会把全队拖进硬仗（城堡团灭两次）。解决：combatDecide 增加
`canHitFromHere`（武器或法术在射程内且LOS可命中）则不移动——远程与施法者保持距离输出，
近战角色照常贴脸；远程型怪物（哥布林/打手/骷髅/格拉斯塔夫/涅兹纳尔）贴脸无额外风险→贴近集火；
治疗者无射程内伤员时向伤员靠拢。经验：**自动策略的移动决策要考虑"职业定位"与"目标类型"**。

### 65. BOSS表决会被倒地玩家死锁（F-30/F-33连带，sim抓出）
sim 在庄园卡死 40 分钟：格拉斯塔夫表决期间瓦洛倒地——倒地玩家处于昏迷无法表决，
而"全员同意才开战"的判定把倒地者也计入必需票 → 表决永远无法完成 → 其余机器人空转让回合。
解决：倒地玩家与离线玩家一样视为弃权（`x.downed` 加入豁免条件）。
经验：**表决类机制要枚举"无法表决者"清单**——离线、倒地、昏迷状态都必须是弃权而不是否决。
